## Regenerating package-lock.json (never use a physical install)

### The rule

**Never** regenerate `package-lock.json` by deleting it and running `npm install`. Always use
`--package-lock-only`.

```bash
npm update --package-lock-only     # move versions
npm install --package-lock-only    # re-apply the esbuild override
```

### Why — the failure this caused

The v0.9.0 lockfile was first regenerated by deleting `package-lock.json` and running a plain
`npm install` on macOS arm64. A *physical* install prunes optional dependencies that do not
match the host platform, so it silently dropped **82 platform packages** — 40 `@napi-rs`,
23 `@rollup`, 19 `@typescript` — leaving only `darwin-arm64` entries. The lockfile looked
fine locally and broke CI on every other platform:

```
Error: Unable to resolve @typescript/typescript-linux-x64. Either your
platform is unsupported, or you are missing the package on disk.
```

TypeScript 7 ships as per-platform native packages, so `npm ci` on Linux had nothing to
resolve. This repo targets macOS arm64, Linux x64 + arm64, and Windows x64 — a
host-pruned lockfile breaks three of the four.

`--package-lock-only` resolves from **registry metadata** rather than the host filesystem, so
it keeps every platform's entries.

### The esbuild override gotcha

`npm update --package-lock-only` alone resolves `esbuild` to 0.27.7 and **ignores the
`esbuild: 0.28.2` override**. You must follow it with `npm install --package-lock-only` to
re-apply the override. Always verify afterwards.

### Verification checklist after any lockfile change

```bash
# platform packages present (expect ~124 with this regex; a host-pruned lockfile gives ~50)
node -e "const l=require('./package-lock.json');console.log(Object.keys(l.packages).filter(k=>/darwin|linux|win32|android|freebsd|musl/.test(k)).length)"

# the package that actually broke CI
grep -c 'typescript-linux-x64' package-lock.json    # must be >= 1

# override survived
node -e "const l=require('./package-lock.json');console.log(l.packages['node_modules/esbuild'].version)"   # expect 0.28.2

npm ci && npm audit && npm test    # expect 0 vulnerabilities, 192 tests pass
```

### Related

`.github/workflows/security.yml` uses `npm install --package-lock-only` for the same reason.
CI installs are `npm ci` everywhere except three deliberate spots: `npm install -g tsx`,
`npm install --no-save typedoc` (docs job), and `examples/configtool-usage`, which has no
committed lockfile of its own.
